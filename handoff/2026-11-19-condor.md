## Added / fixed this session

1. **Driver + routing.** `drivers/condor.py` (`CondorDriver`, subclasses Vantiva),
   in the model menu, claimed from a scanned label by its model code
   `MGA600BVBV5`. `pages.CONDOR_STATION`, `station condor_url` / `--condor-router`.

2. **Web-readiness probe.** Condor's `/` is a `.lp` home that answers **503 while
   logged out** (its landing page is `/login.lp`), so the readiness probe uses
   `ready_path = /login.lp` (the Vantiva keeps `/`). Static files always answer;
   the `.lp` pages 503 under cookie-less load, so power-cycle a unit stuck on 503.

3. **IMEI / modem.** Confirmed on the bench:
   - The modem shows **"Configuring"** with no IMEI for a while after login/reset;
     the station now waits up to `modem_s` (90 s) and re-reads, instead of failing
     on the first read.
   - A modem in **"Airplane Mode"** (radio off, Not Registered) is a dead unit and
     unfixable from the router page — detected fast (no 90 s wait).
   - One line logged: `Mobile network: Power Mode=... ; Registered/Not Registered ; wwan ...`.

4. **Dead-modem (Airplane) handling.** The unit has failed testing on the IMEI and
   the modem cannot be fixed, but the data still needs wiping:
   - Run the factory reset (**DATA-WIPE PASS**),
   - skip the Wi-Fi split and the mobile ping (pointless on a dead modem),
   - **ROUTER-TESTING FAIL** on the IMEI.
   - OLP: `DATA-WIPE PASS, TESTING FAIL-FAIL, REFURB PASS`. Bench-confirmed a
     dead unit now finishes in ~33 s (was ~10 min).

5. **IMEI after the reset (for non-Airplane units).** If the IMEI did not read
   before the reset because the modem was still "Configuring", it is INFO before
   the reset and **re-read after it** — the reset can bring the modem up, and the
   reading after the reset is the one that counts.

6. **Wi-Fi split / Save button.** The Save button stayed disabled (`btn-disable`)
   when the split was done in the session the test had logged in and out of; a
   **fresh session** (a new browser profile, like a new incognito window) enables
   it. The split now starts a fresh session, with a force-click fallback on the
   switch.

## Cellular diagnosis (why some units have no internet)

Read live on a good and a dead unit's Mobile page:

| | Good unit | Dead unit |
|---|---|---|
| Power Mode | Online | Airplane Mode |
| Network Status | Registered (Rogers Wireless) | Not Registered |
| wwan | Connected (IPv4 192.0.0.2) | Disconnected |
| APN | fwach2.apn (set) | fwach2.apn (set) |

The APN is set, so the no-internet units are **not** a customer setting and a
factory reset does not fix them (the user reset several times). There is **no
radio/airplane toggle or reset-modem control** in the Mobile pop-up (Global
Information + Mobile Doctor are read-only). So a dead modem = genuine mobile/SIM
failure = correct to FAIL.
